CLIProxyAPI 原生插件

workbuddy-cpa
腾讯 CodeBuddy 的 Rust 原生插件

把 CodeBuddy（copilot.tencent.com）封装成 CLIProxyAPI 的插件。任何支持 OpenAI / Anthropic 协议的客户端 ——Claude Code、Cursor、Cline、SDK——都能直接调用 CodeBuddy 背后的模型，并附带扫码登录、多账号管理、 每日签到与额度面板。

⬇ 下载 Release ⌨ 查看源码 📦 安装
版本 v0.4.0 Rust · C ABI v1 / RPC schema v3 macOS · Linux · Windows MIT License

为什么是 Rust为什么不写成 Go 插件

CPA 的 Go 插件要求宿主与插件共享包逐字节同源——CPA 每次升级都会让旧插件加载失败。 Rust 版只通过 C ABI 和 JSON RPC 契约与宿主交互，不依赖宿主的 Go 工具链和 SDK 版本，预编译产物下载即用。

版本免疫

宿主升级不会让插件失效，只要 C ABI 与 RPC 契约不变就不需要跟进重编。

跨平台预编译

macOS / Linux / Windows 六个架构的 Release 产物，下载解压即可放进插件目录。

轻量宿主

纯 C ABI 边界，不链接宿主 SDK，不受 CPA Go 版本升级影响。

功能面板里能做什么

所有账号操作都在 CPA 管理面板内完成，凭据生命周期交还宿主接口。

扫码登录 / token 刷新

完全走 CodeBuddy 插件协议；默认凭据 workbuddy.json，多账号各自落在独立文件 workbuddy-{uid后6位}.json。

多账号管理

面板内「＋ 添加账号」（扫码 / 授权链接 + 轮询落盘）、卡片徽章一键启停、悬停 ✕ 删除。

手动批量签到

「每日签到」卡片一键给所有凭据领取签到积分（同 uid 去重，停用账号也签）。签到按北京时间重置，插件不常驻定时器。

chat 执行

OpenAI chat-completions 输入输出；非流式请求自动转上游流式再聚合；跨格式入口（Anthropic 等）自动补 SSE 帧。

额度面板（三区）

账号列表（剩余率进度条 + 最早到期 + 启停徽章）、最近 10 条调用、自绘下拉菜单查看套餐级明细表。

配置驱动模型列表

config.yaml 中改模型列表热生效，无需重编、无需重启。

模型内置默认表

国内版只提供 GLM 系列，避免 CPA 把 DeepSeek / Kimi / Hy3 / MiniMax 的请求路由到 WorkBuddy。 配置里的 models: 只能新增或调整 glm-* 条目，非 GLM 条目会被忽略，executor 也会拒绝非 GLM 模型。

glm-5.1glm-5.2glm-5.3glm-5.3-flashglm-5v-turbo

国际版（workbuddy-intl-cpa，上游 www.workbuddy.ai）只提供 deepseek-v4.1-flash 一个模型，可与国内版同时安装、同时使用。

国际版与 Qoder 插件报同一个模型 id，CPA 按 id 路由，要稳定走国际版请停用另一个。

安装三选一

前置：运行中的 CLIProxyAPI（带 CGO / 插件支持，v7.2.x ~ v8.x 实测可用）。

方式一 · Release 下载（推荐）

从 Releases 下载对应平台 zip，解压出 workbuddy-cpa.dylib / .so / .dll

macOS : workbuddy-cpa_0.4.0_darwin_arm64.zip  /  _darwin_amd64.zip
Linux : workbuddy-cpa_0.4.0_linux_amd64.zip   /  _linux_arm64.zip
Windows: workbuddy-cpa_0.4.0_windows_amd64.zip /  _windows_arm64.zip
国际版  : workbuddy-intl-cpa_0.4.0_<平台>.zip（只提供 deepseek-v4.1-flash）
升级时先删后放（rm workbuddy-cpa.dylib && cp ...，或先拷到临时名再 mv 覆盖）。 直接原地覆盖一个正被运行中的 CPA 映射的 .dylib，会让 macOS 判定该文件代码签名失效， 之后任何 dlopen 它的进程都会被 SIGKILL。万一中招，codesign --force --sign - workbuddy-cpa.dylib 能救回来。

方式二 · 源码编译

git clone https://github.com/xinzengxx/workbuddy-cpa
cd workbuddy-cpa
cargo build --release

rm -f ~/.cli-proxy-api/plugins/workbuddy-cpa.dylib
cp target/release/libworkbuddy.dylib ~/.cli-proxy-api/plugins/workbuddy-cpa.dylib   # macOS
cp target/release/libworkbuddy.so    ~/.cli-proxy-api/plugins/workbuddy-cpa.so      # Linux
cp target/release/workbuddy.dll      <CPA插件目录>/workbuddy-cpa.dll             # Windows

方式三 · 启用（首次安装必做）

CPA 对插件默认全部禁用：全局 plugins.enabled 缺省 false，且 configs 里没有条目的插件一律不加载。 configs 的键必须与插件文件名（去扩展名）一致，即 workbuddy-cpa。 

plugins:
  enabled: true
  dir: "~/.cli-proxy-api/plugins"     # brew launchd 服务必须用绝对路径
  configs:
    workbuddy-cpa: { enabled: true, priority: 100 }
或者更简单：重启后在 CPA 管理面板 → 插件页，对 workbuddy-cpa 点启用（自动写入配置并热加载，无需重启）。
成功标志：日志出现 plugin registered plugin_id=workbuddy-cpa version=0.3.x。

使用接入方式

CPA 默认端口 8317，API key 见 config.yaml 的 api-keys。

协议Base URL
OpenAIhttp://<host>:8317/v1
Anthropichttp://<host>:8317（不带 /v1，走 x-api-key）

自定义模型列表

plugins:
  enabled: true
  configs:
    workbuddy-cpa:
      enabled: true
      models:
        - id: glm-5.3-flash
          name: "GLM-5.3 Flash"
          context: 1000000
        - id: kimi-k3            # 新模型上线后加一行即可

保存后 CPA 热加载（plugin.reconfigure），无需重启或重编。

面板 API额度与账号管理

面板：CPA 管理界面 → WorkBuddy 菜单。

操作位置实现
查看额度 / 套餐明细面板两区GET /v0/management/plugins/workbuddy/accounts
批量签到面板「每日签到」GET .../checkin 查状态；POST .../checkin 领取
添加账号面板「＋ 添加账号」GET .../login/start → POST .../login/poll
启用 / 停用账号卡片徽章点击宿主 PATCH /v0/management/auth-files/status
删除账号卡片右上 ✕宿主 DELETE /v0/management/auth-files
为什么启停 / 删除不走插件自己的接口：实测（CPA v7.2.130）host.auth.save 不会持久化 disabled 字段的改写， 且删掉凭据文件后宿主内存里仍保留该凭据——两者都必须由宿主自己的 auth-files 接口完成。 插件因此只负责模型 / 执行 / 额度，凭据生命周期完全交还宿主。
签到是手动触发：插件不启动后台定时器，打开面板点一次「批量签到」即可。 访问 token 过期时会用 refresh token 自动刷新并原子写回凭据文件； daily-checkin 返回 code=10001（即使外层是 HTTP 400）按「今日已签」处理。

兼容性

宿主 CPA本插件
≥ v7.2.x（C ABI v1 / RPC schema v3）v0.2.0+
≥ v7.2.130（/v0/management/auth-files 启停与删除）v0.3.0+（需多账号管理时）

宿主升级通常无需任何操作；仅当 CPA 变更 C ABI 或 RPC 契约时才需要跟进。 已知限制：CPA v7.2.130 不会调用插件声明的 scheduler.pick 钩子，多账号由宿主内置 round-robin 轮转。
